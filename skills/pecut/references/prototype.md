# Prototype

When: the user wants a mock-up to react to before anything is built.
Not when: a reference image, design file, or page already fixes the look (visual-parity).

1. Run `prototype` on the decision the mock-up has to settle.
2. Stop for the user to pick a direction, or to reject them all.
3. When the user picks one, take the feature playbook with the picked direction as its task.

Done when: the user has picked a direction or rejected them all, and a picked direction is in the feature playbook's todo list.
